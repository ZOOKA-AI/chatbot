# Real Gateway image pilot

Opt-in server setting: `MEDIA_ENGINE_PROVIDER=ai-gateway`. Without it the existing
signed external-worker flow is unchanged. This branch does not activate the
setting or change production credentials.

When enabled, POST /api/media-engine accepts IMAGE/CARTOON from regular workspace
owners only. VIDEO/MAP_3D return 422; a cartoon is a still illustration, not a
story engine or interactive 3D world. Uses the installed AI SDK and Gateway image
model bfl/flux-2-pro, one 1024x1024 image, no SDK retries and a 120-second provider
timeout. Existing AI_GATEWAY_API_KEY (or deployment OIDC) supplies inference auth.
BLOB_READ_WRITE_TOKEN must exist before a job can be admitted.

A transaction-scoped PostgreSQL advisory lock serializes admission per workspace.
All IMAGE/CARTOON jobs created that UTC day (including failures/external-worker
jobs) count toward a hard three-attempt daily pilot cap. The count and insertion
happen in one transaction before any provider call. No new schema is required;
the existing MediaJob table must have been provisioned. A missing table or DB
failure prevents provider spending. This is not a monetary credit/billing system
or a replacement for Gateway budgets. Different workspaces have separate caps;
keep the pilot owner-only until paid entitlement and global admission limits exist.

The request waits for actual generated bytes, uploads them to Blob and commits
the success before returning a jobId. Existing status polling/UI reads the stored
asset URL. Failed generation/upload returns 502 and marks failure where possible;
never returns a constructed success URL. Storage objects are PUBLIC: do not submit
confidential prompts or images to this pilot. Prompts leave the app for the model
provider. If storage succeeds but database commit fails an orphan Blob can remain;
reconcile manually before deleting anything. A killed runtime can leave a queued
job: there is no durable background worker/retry in this pilot. A request retry
counts as another attempt and may spend again; no automatic retries are scheduled.

Tests mock inference and storage, cover output persistence, provider/storage errors,
permissions, unsupported types and rate-limit denial. No live paid inference or
Blob write is performed by these tests. Real hosted PostgreSQL concurrent admission,
actual image output, runtime timeout behavior and a signed-in deployed UI flow
must be validated on staging before enabling for customers. Prior one-image
Gateway proof in chat does not prove this application integration end-to-end.

Release order: review and merge the PR; deploy the exact main commit; configure
the opt-in on the intended environment using an approved change; test one image
from an owner session and inspect the asset and persisted status. Never paste
keys into chat or copy managed agent credentials into the application. No FAL
key or extra provider SDK is required for this path.
